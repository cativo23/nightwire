# Build

The build is a few zero-dependency Node scripts (Node 20 or newer; CI uses 24). Nothing is
minified or reformatted, so a generated file is as readable as the old hand-written one.

## Commands

| Command | Does |
|---------|------|
| `npm run build:tokens` | `src/tokens/tokens.json` → `src/tokens/tokens.css`, `tailwind.preset.js`, `DESIGN.md` regions |
| `npm run build:css` | `src/index.css` → `nightwire.css` |
| `npm run build:cli` | `scripts/build-cli.mjs`: `tsc` (`cli/` → `dist/`), then `dist/package.json` `{"type":"commonjs"}` |
| `npm run build` | all three, in that order |
| `npm test` | `node --test`, which runs every `tests/**/*.test.mjs` |
| `npm run parity` | computed-style comparison of two stylesheets (below) |

The root `package.json` is `"type": "module"` (K5), so the CommonJS output of `tsc` needs the nested
`dist/package.json` to keep loading; `npm run dev` (`tsc --watch`) does not write it until
`build:cli` has run once.

`build:css` needs the `tokens.css` that `build:tokens` writes, so run `npm run build` rather than
the steps on their own.

## Generated files

| File | Generator | Committed | Header |
|------|-----------|-----------|--------|
| `nightwire.css` | `scripts/build-css.mjs` | yes | `/* GENERATED by scripts/build-css.mjs from src/ … */` |
| `tailwind.preset.js` | `scripts/build-tokens.mjs` | yes | `/* GENERATED by scripts/build-tokens.mjs … */` |
| `DESIGN.md` (regions only) | `scripts/build-tokens.mjs` | yes | the `# <generated:NAME>` marker line |
| `src/tokens/tokens.css` | `scripts/build-tokens.mjs` | no (gitignored) | stripped when inlined |
| `dist/` | `scripts/build-cli.mjs` (`tsc` plus `dist/package.json`) | no | — |

`nightwire.css` and `tailwind.preset.js` stay committed at the repo root because consumers read
them straight from the repository (a git submodule, static copies) as well as from npm.

Never edit a generated file. Change its source and rebuild.

## Stylesheet assembly

`src/index.css` is the manifest: `@import "./path.css";` lines and comments, nothing else.
`build-css.mjs` inlines each import in order under a `/* ── src/<path> ── */` banner and keeps the
manifest's comments where they are. A missing file, an import cycle or any other line in the
manifest fails the build and names the file. The order is the cascade; see
[cascade.md](cascade.md).

## Determinism

The same sources always produce byte-identical output: no timestamps, LF line endings, one
trailing newline, key order instead of hash order. Running `npm run build` twice changes nothing
the second time, which is what the CI check relies on.

## CI drift check

`.github/workflows/ci.yml` runs on every pull request and every push to `main`, on Node 20 and 24: `npm ci`,
`npm test`, `npm run build`, then

```sh
git diff --exit-code --stat -- nightwire.css tailwind.preset.js DESIGN.md
```

If the build changed a committed artifact, the job lists the stale files and fails with
"Generated artifacts are stale: run npm run build and commit." It then builds the docs site in
`apps/docs`, which imports the root stylesheet and preset, so a change that breaks the site fails
before merge rather than in the deploy.

## Parity tool

`scripts/parity/compare.mjs` proves that two stylesheets render the same. It is how the
restructure was verified, and it is the check to run before any change that should not be
visible. It is not in CI because it needs a local Chrome. Usage and options are in
[CONTRIBUTING.md](../../CONTRIBUTING.md#checking-that-nothing-changed-visually).

### Change categories (`--expect`)

For an intended visual change, `--expect <file>` turns the check from "nothing differs" into
"nothing differs that a declared category does not explain". The file is validated, compiled once
and applied to the structured difference records; the pure pieces live in
`scripts/parity/lib/diff.mjs` (`validateCategories`, `classify`), `lib/baseline.mjs`
(`resolveOld`), `lib/control.mjs` (`loadControl`, `withControl`), `lib/glob.mjs` (the one glob
used by `--pages` and `match.page`) and `lib/report.mjs` (report layout and exit code), each covered by a test in `tests/`.

- **Matching.** A record `{ page, state, path, prop, old, new }` is expected when one category
  matches every `match.*` field it declares. `prop` is required; `path`, `state`, `old` and `new`
  are unanchored regexes, `page` is a glob. The first matching category in file order takes the
  difference, so counts plus unexpected equal the total.
- **Output.** Only unexpected `DIFF` lines print (still capped by `--max-lines`), followed by one
  `CATEGORY  <id>  <count>` line per category in file order (unused ones show 0), the `COVERAGE`
  line, and `RESULT  differences=N  unexpected=M`. Without `--expect` the output is the classic
  `DIFF` lines, `COVERAGE` and `RESULT  differences=N`.
- **Baseline.** The file's top-level `baseline` (a git ref such as `v2.1.0`) is optional. With
  `--expect` and no `--old`, the old side is `git:<baseline>`, or `git:main` when the file has no
  baseline. An explicit `--old` that differs from the baseline still runs, after one
  `WARN  --old <x> differs from the category baseline <y>` line before the `PARITY` line. The
  decision is `resolveOld` in `lib/baseline.mjs`. Without `--expect`, `--old` defaults to
  `git:main` as before.
- **Exit code.** 0 only when `unexpected=0` and coverage is full; 1 otherwise; 2 when the file is
  unreadable, not JSON or invalid (checked before Chrome starts).
- **Cascade categories and `--control`.** A category may declare `"kind": "cascade"` for geometry
  that an ancestor's open layout moves (FR-038). `validateCategories` accepts it only when
  `match.path` and `match.page` are set, `match.path` cannot match `:root` or `@keyframes` (the
  records for custom properties and keyframes), and `match.prop` has the closed form `^name$`,
  `^(name|name)$` or `^(?:name|name)$` over `width`, `height`, `inline-size`, `block-size`,
  `transform-origin` and `perspective-origin`. It is a closed form, not a probe against a property
  list, because the snapshot also records custom properties and keyframe names that no list can
  enumerate.
  `--control <css>` (needs `--expect`, `lib/control.mjs`) appends the sheet to the new stylesheet,
  makes `classify(…, { control: true })` skip the cascade categories, and prints
  `CONTROL  sheet=<path>  cascade-categories-ignored=N` before `RESULT`. A control run with
  `unexpected=0` is the evidence that the cascade categories name the real cause; without it they
  prove nothing. Exit codes are unchanged, and `--json` records `meta.control`.

A state label joins its parts with `|` (`combat|rm-off`, then `|:hover@<path>` for a forced
pseudo-state), and `match.state` is a regex, so an unescaped `|` is alternation:
`"combat|rm-off"` also matches `archive|rm-off`. Write `"^combat\\|rm-off"` to pin one label.

The file format, with every field, is in
[CONTRIBUTING.md](../../CONTRIBUTING.md#declaring-intended-changes-with---expect).
